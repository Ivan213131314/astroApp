# Astro Circle

**Мобильное приложение об астрологии, совместимости и самопознании на Flutter.**

Astro Circle объединяет гороскопы, натальные разборы, нумерологию и анализ ладони по фотографии. Приложение учитывает данные профиля и рождения, использует AI для текстовых интерпретаций и сохраняет историю разборов в Firebase.

> Исходный код приложения находится в папке [`fl_astro_circle/`](fl_astro_circle). Все команды Flutter ниже выполняются из этой папки.

## Возможности

- **Гороскопы** — прогнозы для 12 знаков зодиака на сегодня, завтра и неделю. Разделы: общий прогноз, отношения, работа и здоровье.
- **Натальный разбор** — определение солнечного, лунного и восходящего знаков с краткими и подробными AI-интерпретациями.
- **Совместимость** — разбор отношений по данным рождения двух людей.
- **Нумерология** — расчёт числа жизненного пути и генерация персонального описания.
- **Анализ ладони** — выбор фотографии и её обработка моделью с поддержкой изображений.
- **Профиль и история** — онбординг, данные рождения, интересы, сохранённые натальные разборы, результаты совместимости и нумерологии.
- **Авторизация** — email и пароль, Google, Sign in with Apple.
- **Подписка** — интеграция экранов оплаты через Superwall.

В проекте также есть раздел «Послание Вселенной», экраны общения с астрологами и ресурсы локализации для английского, хинди, индонезийского, китайского и арабского языков. Полнота перевода отдельных экранов может различаться.

## Запуск

### 1. Подготовьте окружение

- Flutter **3.32.0 или новее** с Dart **3.8.0 или новее**, в пределах Dart 3.x — по ограничениям текущего `pubspec.lock`.
- Для Android: Android SDK 35, JDK 17 и устройство или эмулятор с Android API 26+.
- Для iOS: macOS, Xcode и CocoaPods; в `ios/Podfile` указана минимальная версия iOS 14.
- Для серверных функций: Node.js **20**, npm и Firebase CLI.

Проверьте окружение:

```bash
flutter doctor
```

### 2. Получите исходники

```bash
git clone https://github.com/Ivan213131314/astroApp.git
cd astroApp/fl_astro_circle
flutter pub get
```

### 3. Подключите Firebase

Создайте свой проект Firebase и зарегистрируйте приложения Android и iOS с идентификаторами, соответствующими вашим настройкам сборки.

1. Включите Authentication и нужные способы входа: Email/Password, Google и Apple.
2. Создайте базу Cloud Firestore.
3. Подключите конфигурацию своего проекта:
   - Android: `android/app/google-services.json`;
   - iOS: `ios/Runner/GoogleService-Info.plist`.
4. Для Google Sign-In на Android добавьте SHA-1 сертификата, а для Apple Sign-In настройте capability в Xcode.

Подробности: [настройка Firebase](fl_astro_circle/FIREBASE_SETUP.md).

Для iOS установите зависимости на macOS:

```bash
cd ios
pod install
cd ..
```

### 4. Настройте внешние сервисы

Пути в таблице указаны относительно `fl_astro_circle/`.

| Сервис | Где настраивается |
| --- | --- |
| OpenRouter: клиентские AI-запросы | `lib/config/api_config.dart` — `openRouterApiKey`, `aiModel`, `visionModel` |
| OpenRouter: генерация гороскопов | `functions/index.js` — `OPENROUTER_API_KEY`, `AI_MODEL` |
| Google Places | `googleApiKey` в `lib/pages/onboarding/place_of_birth_screen.dart` и `lib/pages/natalChart/natal_chart.dart` |
| Superwall | Вызов `Superwall.configure(...)` в `lib/main.dart` и настройки в Superwall Dashboard |

Используйте собственные учётные данные и проверьте доступность выбранных моделей OpenRouter. Модель для анализа ладони должна поддерживать изображения. Автоматическая загрузка настроек из `.env` в текущем коде не реализована.

Для Superwall предусмотрены события `onboarding_premium` и `subscribe_button`. Подключение продуктов и экранов подписки описано в [инструкции Superwall](fl_astro_circle/SUPERWALL_SETUP.md).

**Режим разработки:** в `lib/config/debug_config.dart` включён `skipPaywall = true`: экран оплаты пропускается, а покупка имитируется. Для проверки реальных подписок установите `skipPaywall = false` и настройте продукты магазинов.

Секретные ключи OpenRouter не следует публиковать в репозитории или включать в распространяемую сборку. Для выпуска приложения клиентские AI-запросы следует перенести на сервер с защищённым хранением ключа.

### 5. Запустите приложение

После настройки сервисов подключите устройство или запустите эмулятор:

```bash
flutter devices
flutter run
```

Для выбора конкретного устройства используйте `flutter run -d DEVICE_ID`, заменив `DEVICE_ID` значением из `flutter devices`.

## Серверная генерация гороскопов

Flutter-приложение читает гороскопы из коллекции `horoscopes` в Firestore. Их создаёт функция `generateDailyHoroscopes`: каждый день в **00:00 UTC** она обрабатывает 12 знаков и три периода — `today`, `tomorrow`, `this_week`.

Для собственного окружения настройте Firebase CLI, проект с тарифом Blaze и OpenRouter в серверном коде. Затем из `fl_astro_circle/` выполните:

```bash
firebase login
firebase use --add
cd functions
npm ci
cd ..
firebase deploy --only functions,firestore
```

Эта команда публикует функции, правила и индексы Firestore в выбранный проект. Для первого наполнения базы предусмотрена HTTP-функция `generateHoroscopesManual`; её вызов запускает генерацию через OpenRouter.

Документ гороскопа имеет идентификатор:

```text
{zodiacSign}_{YYYY-MM-DD}_{period}
```

Например: `aries_2026-01-01_today`.

Подробнее: [развёртывание Cloud Functions](fl_astro_circle/FIREBASE_FUNCTIONS_DEPLOYMENT.md). Для версии Node.js ориентируйтесь на `functions/package.json`, где указана версия 20.

## Особенности текущей версии

- Расчёт лунного и восходящего знаков упрощён; проект не использует полноценный астрономический движок с эфемеридами.
- Экран `AstrologerChatScreen` использует заранее заданные ответы. Наличие сервиса AI и экранов чата не означает, что каждый экран общения подключён к модели или живому консультанту.
- В `pubspec.yaml` объявлена папка `assets/universe/`, которой нет в репозитории. Если сборка сообщает об отсутствии этой папки, добавьте необходимые ресурсы или уберите неиспользуемую запись.
- `test/widget_test.dart` содержит стандартный тест счётчика Flutter и требует обновления под реальные экраны приложения.
- Android release-конфигурация пока использует отладочную подпись. Для публикации нужна собственная настройка signing.

Для статического анализа выполните:

```bash

```
